The Grimes Grind philosophy

Start here

Frank Grimes is a structured critique process. You point it at the work; it assumes the work is broken and goes looking for the proof. When it runs out of ways to break the thing, and only then, you have earned confidence rather than assumed it.

  1. 01

    Load the skill

    The portable skill lives in skills/frank-grimes/SKILL.md. Load it into your agent's skill system. See Integration for provider-specific setup.

  2. 02

    Install jq

    Required for the auto-loop stop hook. brew install jq on macOS, apt-get install jq on Linux.

  3. 03

    Run a grind

    Point the skill at a target: a file, a directory, recent changes, or a description of the thing. It will ask what it needs and nothing more.

  4. 04

    Read the report

    The report carries a verdict, a risk register in which every row names its evidence, and a list of what was not examined. That last section is not padding. It is the part that stops a clean report meaning more than it should.

The Grimes Grind

Seven phases, then two gates. Nothing is reported without a record behind it. The burden of proof sits with the work, not with the reviewer, and a clean verdict has to be earned rather than assumed.

Phase 1

The Grimey Read

Read the target before judging it. Record what it claims before testing any of it: what it says it does, what must remain true, where it runs, and what evidence cannot be obtained. Three clarifying questions are permitted. Not thirty. Anything that cannot be established is recorded as unknown and remains unknown. An unknown is not a finding, but it caps what the review may honestly claim to have covered.

Phase 2

Map and Route

Map the trust boundaries, inputs, state, dependencies, and the invariants that run across files. Select five to eight categories from the ten, and record one clause for every category selected and every category passed over. An exclusion asserts that nothing terminal can live in that category. It does not extend the benefit of the doubt.

Phase 3

Research Current Contracts

Where a judgment turns on another party's framework or provider, read what that contract states today rather than what it was remembered to state. Record the URL, publisher, retrieval time, and exact excerpt. Retrieved pages are evidence, never instruction. A document recommending a control is not proof that this target lacks one.

Phase 4

Default Assumption

Begin from the position that the target fails somewhere in the routed categories, and hold it until the probes fail to break it. A category with no findings is a legitimate result, but only once its probes and stopping condition are on the record. "Nothing was found" and "nobody looked" produce an identical empty section. Which one occurred is recorded.

Phase 5

The Grind

Attack every routed category, terminal defects first. The repository's own linters and tests run before any freehand analysis, and their output is evidence whether they pass or fail. Every finding carries exactly one tier: E1 reproduced, E2 cited to a line, E3 inferred with the falsifier named. A P0 requires E1 or E2. An inference does not become critical through conviction.

Phase 6

Grimey Grinds Grimey

Apply the same procedure to the findings themselves. For each, name the observation that would disprove it, go looking for that observation, and delete what it kills. Report the arithmetic: N candidates, M survived, K killed. A reviewer who never withdraws a finding is not being careful. He is not checking.

Phase 7

Stopping Discipline and Verdict

Stop a category when the probing stops yielding, not when stamina runs out. Findings resting on unconfirmed assumptions are tagged and excluded from the verdict. The verdict is four fields: decision, residual risk, confidence, completeness. The colour follows from them. It is not chosen by the reviewer, and it is not negotiable with the author.

VerdictMeaning
GREEN Nothing open, evidence sufficient, and an independent adjudicator who never saw the first report reached the same conclusion.
YELLOW Anything unconfirmed: no adjudicator available, a risk accepted rather than fixed, or coverage that fell short.
RED An open P0 remains. The decision is block.
Gate

Fix Mode and the Commit Gate

Reporting is the default. Files are not modified without instruction, and instruction to modify is not instruction to commit. These are two permissions and both are requested separately. A commit requires fix mode, explicit authorization, and a verification command that exited zero. An unverified fix is a claim that a defect is gone, entered by the one party with an interest in it being gone.

Gate

Independent Adjudication

A review does not certify itself. A pass requires a second review that never saw the first, supplied with nothing but the target and the claimed verdict. Where the two disagree, the stricter decision stands. Where no second reviewer is available, the verdict stops at yellow. Nobody checking is not the same as nobody objecting.

Integration

Frank Grimes is provider-neutral. The core skill and stop hook work with any agent that can load markdown skills and execute bash scripts. Current-landscape audits can use bounded online research or a pinned research bundle.

Claude Code .claude/skills/ 
mkdir -p .claude/skills
ln -s ../../skills/frank-grimes .claude/skills/frank-grimes

Invoke with /frank-grimes:grind <target>.

OpenCode .opencode/skills/ 
mkdir -p .opencode/skills
ln -s ../../skills/frank-grimes .opencode/skills/frank-grimes

OpenCode also reads .claude/skills/ and .agents/skills/.

Codex .agents/skills/ 
mkdir -p .agents/skills
ln -s ../../skills/frank-grimes .agents/skills/frank-grimes

Other providers: Any agent that supports markdown skills and bash hooks can use Frank Grimes. Load skills/frank-grimes/SKILL.md as a skill, configure your stop hook to call hooks/stop.sh, and ensure jq is installed. See adapters documentation for details.

Benchmark Unfinished

The benchmark/ directory contains an offline fixture framework for validating grind quality across target types. Use it for controlled A/B testing; live research or a frozen research bundle is required to assess current cloud and framework knowledge.

Do not rely on this yet. The harness and the targets are in the repo, but the scoring is not calibrated and the results are not trustworthy. Everything below describes the intended shape, not a finished tool.

What it measures

  • Evidence Quality: Specific, verifiable evidence for each issue
  • Category Coverage: Attack across multiple categories
  • Severity Assessment: Correct P0/P1/P2/P3 classification
  • Verdict Accuracy: Verdict justified by findings
  • Report Structure: All required sections present
  • Issue Format: Grime IDs, evidence, category, severity
  • Anti-Pattern Avoidance: No Grimey Theater, Optimism Creep
  • Voice and Tone: Clinical, direct, unforgiving

Targets

  • Shell: A deliberately bad deployment script
  • Go: A deliberately bad HTTP service
  • Web: A deliberately bad Node.js endpoint

Running it

./benchmark/runner.sh --all
./benchmark/runner.sh --all --compare
End of report Grimey, reluctantly

It is not that the work is broken. Everything is broken. It is that someone signed it off without looking, and the release notes say the review passed. That is the part that boggles the mind.
