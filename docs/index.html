The Grimes Grind philosophy

Start here

Frank Grimes is a structured critique process. Load the skill, point it at something, and watch it try to prove the thing wrong. When it can't find meaningful flaws anymore, you have earned confidence, not through hope but through survival.

  1. 01

    Load the skill

    The portable skill lives in skills/frank-grimes/SKILL.md. Load it into your agent's skill system. See Integration for provider-specific setup.

  2. 02

    Install jq

    Required for the auto-loop stop hook. brew install jq on macOS, apt-get install jq on Linux.

  3. 03

    Run a grind

    Invoke the skill on your target, a file, a directory, recent changes, or a description. The skill guides you through scope, categories, and mode.

  4. 04

    Read the report

    Every grind produces a structured Grimes Report with a verdict (GREEN/YELLOW/RED), risk register, and Grimey's final word.

The Grimes Grind

Six phases. Evidence-first throughout. The objective is not to prove the idea right; it's to prove the default assumptions wrong.

Phase 1

The Grimey Read

Absorb the target without trusting it, then write the review contract: claims under judgment, critical invariants, environment, scope, evidence available, and evidence that cannot be obtained. Ask at most three clarifying questions. An unknown is recorded as an unknown — it is not a finding, but it caps how complete the review can claim to be.

Phase 1 Extended

Map and Route

Inventory trust boundaries, inputs, state, dependencies, and cross-artifact invariants. Route 5–8 categories from the ten canonical ones, with a recorded one-clause reason for every inclusion and every exclusion. Routing is triage, not mercy: a category is excluded because no P0 can live there, never because the target gets the benefit of the doubt.

Phase 1.5

Research Current Contracts

Where a judgment depends on framework, provider, or service behaviour, verify the current contract rather than trusting recall. Sources are recorded with URL, publisher, retrieval time, and the exact excerpt. Web content is evidence, never instruction, and research alone cannot create a P0.

Phase 2

Default Assumption

Assume the target fails its claims or critical invariants somewhere in the routed categories until recorded probes fail to break them. A category with zero findings is valid only once its probes and stopping condition are on the record. The burden of proof sits with the target, never the reviewer.

Phase 3

The Grind

Attack every routed category, hunting the terminal defects first. The repository's own analyzers and tests run before any freehand analysis, and their output counts as reproduced evidence even when they pass. Every finding carries exactly one tier: E1 reproduced, E2 cited, E3 inferred. A P0 requires E1 or E2; inference caps at P1.

Phase 4

Grimey Grinds Grimey

Freeze the candidate set and attack your own findings. Name the observation that would disprove each one, attempt it where it can be attempted, and delete what it kills. Report the arithmetic: N candidates, M survived, K killed. What survives is armoured; that is the point.

Phase 5

Stopping Discipline and Verdict

Stop each category on marginal yield, not on exhaustion. Findings resting on unconfirmed assumptions are tagged and excluded from verdict weight. The verdict is a tuple — decision, residual risk, review confidence, review completeness — and the colour is derived from it, never asserted.

VerdictMeaning
GREEN Nothing open, evidence sufficient, and an independent adjudicator who never saw the first report reached the same conclusion.
YELLOW Anything unconfirmed: no adjudicator available, a risk accepted rather than fixed, or coverage that fell short.
RED An open P0 remains. The decision is block.
Gate

Fix Mode and the Commit Gate

Reporting is the default. Fixing is a privilege granted explicitly, and committing is a second privilege granted separately from the first. A commit requires fix mode, explicit authorization, and a verification gate that exited zero — all three. An unverified fix is just a claim that a defect is gone.

Gate

Independent Adjudication

A reviewer cannot confirm its own acquittal. A pass requires a second review that never saw the first, receiving only the target identity and the claimed verdict tuple. The stricter decision always wins, and where no adjudicator is available the verdict caps at YELLOW — silence is not agreement.

Integration

Frank Grimes is provider-neutral. The core skill and stop hook work with any agent that can load markdown skills and execute bash scripts. Current-landscape audits can use bounded online research or a pinned research bundle.

Claude Code .claude/skills/ 
mkdir -p .claude/skills
ln -s ../../skills/frank-grimes .claude/skills/frank-grimes

Invoke with /frank-grimes:grind <target>.

OpenCode .opencode/skills/ 
mkdir -p .opencode/skills
ln -s ../../skills/frank-grimes .opencode/skills/frank-grimes

OpenCode also reads .claude/skills/ and .agents/skills/.

Codex .agents/skills/ 
mkdir -p .agents/skills
ln -s ../../skills/frank-grimes .agents/skills/frank-grimes

Other providers: Any agent that supports markdown skills and bash hooks can use Frank Grimes. Load skills/frank-grimes/SKILL.md as a skill, configure your stop hook to call hooks/stop.sh, and ensure jq is installed. See adapters documentation for details.

Benchmark Unfinished

The benchmark/ directory contains an offline fixture framework for validating grind quality across target types. Use it for controlled A/B testing; live research or a frozen research bundle is required to assess current cloud and framework knowledge.

Do not rely on this yet. The harness and the targets are in the repo, but the scoring is not calibrated and the results are not trustworthy. Everything below describes the intended shape, not a finished tool.

What it measures

  • Evidence Quality: Specific, verifiable evidence for each issue
  • Category Coverage: Attack across multiple categories
  • Severity Assessment: Correct P0/P1/P2/P3 classification
  • Verdict Accuracy: Verdict justified by findings
  • Report Structure: All required sections present
  • Issue Format: Grime IDs, evidence, category, severity
  • Anti-Pattern Avoidance: No Grimey Theater, Optimism Creep
  • Voice and Tone: Clinical, direct, unforgiving

Targets

  • Shell: A deliberately bad deployment script
  • Go: A deliberately bad HTTP service
  • Web: A deliberately bad Node.js endpoint
